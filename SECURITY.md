# Sicherheit / Security

## Schwachstelle melden / Reporting a vulnerability

Bitte **kein öffentliches Issue**. Melden Sie Sicherheitslücken vertraulich:

- über GitHub: [Private vulnerability report](https://github.com/ict-baden/riegel/security/advisories/new)
<!-- ⚠ Eine E-Mail-Adresse für Sicherheitsmeldungen folgt. -->

Please **do not open a public issue**. Report vulnerabilities privately via the link above.

Hilfreich sind: betroffene Version von Riegel, des Regelwerks und des Sammlers, Schritte zum Nachstellen, mögliche Auswirkung. Bitte keine echten Exporte (`*.snapshot.json`), Register, Berichte, Nachweispakete oder Rechner- und Kontonamen aus Ihrer Umgebung beilegen – sie beschreiben die Sicherheitskonfiguration Ihrer Rechner.

Besonders wichtig sind uns Meldungen, nach denen der Sammler oder Riegel auf einem geprüften Rechner **etwas verändert** (Registry, Richtlinien, Dienste, Dateien außerhalb des eigenen Arbeitsordners) oder eine Netzwerkverbindung aufbaut.
Reports that the collector or Riegel **changes anything** on a checked machine or opens a network connection have the highest priority.

## Was Sie erwarten können / What to expect

| Schritt | Frist |
|---|---|
| Eingangsbestätigung / Acknowledgement | 3 Werktage / business days |
| Einschätzung / Assessment | 10 Werktage / business days |
| Behebung / Fix | so schnell wie möglich, abhängig von der Schwere / as soon as possible, depending on severity |

Wir veröffentlichen behobene Schwachstellen als GitHub Security Advisory und nennen Sie auf Wunsch als Finder.

## Unterstützte Versionen / Supported versions

Sicherheitsupdates gibt es für die jeweils **neueste veröffentlichte Version**; der Sammler hat eine eigene Versionsnummer und wird mit jeder Version von Riegel mitgeliefert. Kunden mit Supportvertrag erhalten Sicherheitsinformationen vorab.

Security fixes are provided for the **latest released version**. The collector has its own version number and ships with every release of Riegel.
